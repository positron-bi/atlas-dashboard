# داشبورد مالی اطلس

نسخهٔ وب گزارش Power BI با دو صفحهٔ «سود و زیان» و «بودجه و عملکرد». ظاهر و ناوبری با داشبوردهای قبلی هم‌خانواده است. فیلترهای سال و ماه دارد و سال پیش‌فرض ۱۴۰۵ است. صفحهٔ `Accounting` و جزئیات سند/حساب در انتشار عمومی وجود ندارند.

## اجرای محلی

از پوشهٔ پروژه اجرا کنید:

```powershell
python -m http.server 4173
```

سپس `http://127.0.0.1:4173` را باز کنید.

## انتشار

بعد از اینکه ریپازیتوری خالی `positron-bi/atlas-dashboard` در GitHub ساخته شد، این پوشه را اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish-to-github.ps1
```

بعد در ریپو از مسیر **Settings → Pages → Build and deployment → Deploy from a branch**، شاخهٔ `main` و پوشهٔ `/(root)` را انتخاب کنید. Pages سایت استاتیک را از فایل‌های همین ریپو می‌سازد.

## منبع و محدودیت داده

فایل `data/dashboard-data.json` یک snapshot تجمیعی از مدل `atlas.pbix` است که در ۱۷ اکتبر ۲۰۲۶ استخراج شد. ارقام فقط به تفکیک سال/ماه و گروه درآمد/هزینه‌اند؛ ریز اسناد، شماره سند، شرح، نام حساب و شناسه‌های جزئی منتشر نمی‌شوند. فایل PBIX نیز با `.gitignore` از Git کنار گذاشته شده است.

مقیاس نمایش میلیارد تومان است (ریال ÷ ۱۰٬۰۰۰٬۰۰۰٬۰۰۰). در P&L از جدول و گروه‌بندی صفحهٔ P&L استفاده شده؛ در صفحهٔ بودجه/عملکرد، عملکرد واقعی از measureهای همان صفحه محاسبه شده است. به همین دلیل بعضی ماه‌ها ممکن است بین دو صفحه اختلاف داشته باشند: خود مدل Power BI دو جدول واقعی متفاوت برای این دو صفحه به‌کار می‌برد. هزینه در جدول/نمودار به‌شکل مثبت نشان داده می‌شود، اما سود مطابق علامت مبالغ مدل از درآمد + هزینهٔ علامت‌دار محاسبه می‌شود. ماه‌های آینده مقدار عملکرد و تحقق ندارند و خالی می‌مانند.

محاسبات Python در `python/atlas_calculations.py` تعریف و اعتبارسنجی شده‌اند:

- درآمد/هزینهٔ P&L: جمع خالص ماهانه از مدل.
- سود/زیان P&L: درآمد + هزینهٔ علامت‌دار.
- تحقق درآمد و هزینه: عملکرد ÷ بودجه.
- سود بودجه: بودجهٔ درآمد + بودجهٔ هزینهٔ علامت‌دار.
- سود واقعی و انحراف: همان measureهای مدل (درآمد واقعی + هزینهٔ واقعی؛ عملکرد − بودجه).

برای اجرای کنترل محاسبات:

```powershell
python .\python\atlas_calculations.py
```

## رفرش روزانه ساعت ۳ صبح

کد رفرش `python/refresh_from_sql.py` فقط دو مجموعهٔ جمع ماهانه از SQL Server می‌خواند؛ هیچ نتیجهٔ ریزسندی در JSON عمومی نوشته نمی‌شود. سرور از روی اطلاعات اتصال Power BI شناخته شد، اما آدرس و اطلاعات دسترسی داخل ریپوی عمومی قرار داده نشده‌اند. برای فعال‌کردن رفرش:

1. Python، `pyodbc` و درایور Microsoft ODBC for SQL Server را نصب کنید.
2. فایل محلی `.env.local` را کنار README بسازید؛ این فایل نادیده گرفته و منتشر نمی‌شود:

   ```text
   SQL_SERVER=آدرس-قابل-دسترسی-سرور
   SQL_DATABASE=mali
   SQL_DRIVER=ODBC Driver 18 for SQL Server
   ```

   در صورت نیاز به SQL Authentication، `SQL_USERNAME` و `SQL_PASSWORD` را فقط در همین فایل محلی بنویسید. رمز را commit نکنید.

3. ابتدا اجرای دستی را تأیید کنید:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\refresh-and-publish.ps1
   ```

4. پس از تأیید اتصال و اولین push، برای ثبت اجرای روزانهٔ ساعت ۳ به وقت محلی ویندوز:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\install-daily-refresh-task.ps1
   ```

این زمان‌بندی تا اجرای مرحلهٔ ۴ نصب نمی‌شود. کامپیوتر باید روشن و کاربر وارد ویندوز باشد، SQL Server از آن در دسترس باشد و GitHub credential برای push معتبر بماند. دادهٔ Pages نیز فقط پس از موفق‌شدن اتصال و push تغییر می‌کند.
